#### Question 1: A Massive E-commerce Company is Collecting Data that is Generated by Its Customers for Analysis by Using an Amazon [[Amazon S3 Fundamentals|S3]] Data Lake. Some of the Data Being Collected and Stored in Amazon [[Amazon S3 Fundamentals|S3]] Includes Personally Identifiable Information (PII).The Company Wants a Data Engineer to Design an Automated Solution to Identify New and Existing Data that Needs PII to Be Masked before Analysis is Performed. Additionally, the Data Engineer Must provide an Overview of the Data that is Identified for the Security Audit Team. The Task of Masking the Data Will Be Handled by an Application Already Created in the AWS account

The data engineer needs to design a solution that can invoke this application in real time when PII is found.

Which solution will meet these requirements with the LEAST operational overhead?

- [ ] Create an AWS [[Lambda]] function to analyze data for PII. Configure notification settings on the [[Amazon S3 Fundamentals|S3]] bucket to invoke the [[Lambda]] function when a new object is uploaded.
- [ ] Configure notification settings on the [[Amazon S3 Fundamentals|S3]] bucket. Configure an Amazon EventBridge rule for the default event bus for new object uploads. Set the masking application as the target for the rule.
- [x] Enable Amazon [[Macie]] in the AWS account. Create and Amazon EventBridge rule for the default event bus for [[Macie]] findings. Set the masking application as the target for the rule.
- [ ] Enable Amazon [[Macie]] in the AWS account. Create an AWS [[Lambda]] function to run on a schedule to poll [[Macie]] findings and invoke the masking application.

**Reason**: EventBridge triggers the application only when necessary.
#### Question 2: A Data Engineering Team is Building a Data Lake on Amazon [[Amazon S3 Fundamentals|S3]]. They Need to Ingest Large Volumes of Data from Various Sources, including On-premises Databases and other AWS Services. The Team is Looking for the Most Efficient and Cost-effective way to Ingest Data into [[Amazon S3 Fundamentals|S3]]

Which of the following is the MOST efficient and cost-effective way to ingest large volumes of data into Amazon [[Amazon S3 Fundamentals|S3]] from various sources, including on-premises databases?

- [ ] Create a [[VPC Networking Fundamentals|VPC]] Gateway Endpoint for Amazon [[Amazon S3 Fundamentals|S3]] and use AWS Direct Connect
- [x] Create a [[VPC Networking Fundamentals|VPC]] Interface Endpoint for Amazon [[Amazon S3 Fundamentals|S3]] and use AWS Direct Connect
- [ ] Create a [[VPC Networking Fundamentals|VPC]] Gateway Endpoint for Amazon [[Amazon S3 Fundamentals|S3]] and use a site-to-site VPN
- [ ] Create a [[VPC Networking Fundamentals|VPC]] Interface Endpoint for Amazon [[Amazon S3 Fundamentals|S3]] and use a site-to-site VPN

**Reason**: Interface endpoints are better suited for high-throughput scenarios.

#### Question 3: Your Company Operates a Large E-commerce Platform with Multiple Data Warehouses in Amazon [[Redshift Data Loading COPY|Redshift]]. The Marketing Team Needs to Analyze Customer Data, including Purchase History, Demographics, and Browsing Behavior, to Personalize Product Recommendations. They Should only Have Read Access to Specific Data Sets without Compromising Data Security and Governance. Additionally, the Data Must Be Up-to-date and Consistent across All Regions

Which approach would you recommend to meet these requirements?

- [ ] Create a separate Amazon [[Redshift Data Loading COPY|Redshift]] cluster and export data from the existing clusters to the new cluster for the marketing team.
- [ ] Grant the marketing team's [[AWS IAM]] roles access to the existing Amazon [[Redshift Data Loading COPY|Redshift]] clusters with specific SQL permissions.
- [x] Have the marketing team spin up a new [[Redshift Data Loading COPY|Redshift]] cluster and use Amazon [[Redshift Data Loading COPY|Redshift]] data sharing to securely share data across clusters.
- [ ] Export data from Amazon [[Redshift Data Loading COPY|Redshift]] to Amazon [[Amazon S3 Fundamentals|S3]] using the UNLOAD command. Have the marketing team query the data in Amazon [[Amazon S3 Fundamentals|S3]] using Amazon [[AWS Data Engineer Zettelkasten Lite style/Athena]].

**Reason**: [[Redshift Data Loading COPY|Redshift]] data sharing allows to securely share data across clusters without creating copies or moving the data.

#### Question 4: A Company is Running a Cloud-based Software Application in an Amazon [[EC2|EC2]] Instance Backed by an Amazon [[RDS and Aurora Fundamentals|RDS]] for Microsoft SQL Server Database. The Application Collects, Processes, and Stores Confidential Information and Records in the Database. The Company Wants to Eliminate the risk of Credential Exposure

Which solution will meet this requirement?

- [ ] Use AWS Identity and Access Management ([[AWS IAM]]) database authentication to configure authentication to the [[RDS and Aurora Fundamentals|RDS]] for Microsoft SQL Server database
- [ ] Use AWS Systems Manager Parameter Store to store the credentials. Configure automatic rotation in Parameter Store to rotate the credentials every 30 days
- [ ] Use AWS Security Token Service (AWS STS) to configure authentication to the [[RDS and Aurora Fundamentals|RDS]] for Microsoft SQL Server database
- [x] Use AWS Secrets Manager to store the credentials. Configure automatic rotation in Secrets Manager to rotate the credentials every 30 days.

**Reason**: Applications code or config files need access to credentials. AWS Secrets Manager is best for this purpose.


#### Question 5: An International Investment Banking Firm Frequently Uploads 100 MB Files to Amazon [[Amazon S3 Fundamentals|S3]] for Analysis with Amazon [[AWS Data Engineer Zettelkasten Lite style/Athena]]. Recently, it Was Discovered that Some Uploads Have Become Corrupted, Causing a Critical Big Data Job to Fail. As a Recently Hired Data Engineer, the Company is Looking to You to Find a Solution that Will Ensure the Successful Upload of the Files and a way to Verify that the Files Contents Remain Unchanged from On-premises to Amazon [[Amazon S3 Fundamentals|S3]]

Which of the following recommendations would you make that are the MOST cost effective?

- [ ] Use the AWS CLI to upload files with the -- sse parameter for server-side encryption, ensuring data integrity during transit.
- [x] Utilize the [[Amazon S3 Fundamentals|S3]] Multipart upload feature with MD5 checksum validation for each part, providing a strong guarantee that files are uploaded successfully and remain unaltered.
- [ ] Enable versioning on the [[Amazon S3 Fundamentals|S3]] bucket to keep multiple versions of an object, allowing the company to revert to uncorrupted versions if necessary.
- [ ] Implement [[Amazon S3 Fundamentals|S3]] Transfer Acceleration to increase the speed of file transfers and reduce the likelihood of corruption due to connection issues.

**Reason**: MD5 checksum validation for each part ensures integrity.

1. Your application on EC2 creates images thumbnails after profile photos are uploaded to Amazon S3.These thumbnails can be easily recreated, and only need to be kept for 60 days. The source images should be able to be immediately retrieved for these 60 days, and afterwards, the user can wait up to 6 hours. How would you design this?

Source Images: Use the *Standard* tier with a lifecycle configuration to transition them to Glacier after 60 days.

Thumbnails: use the One-Zone IA tier with a lifecycle configuration to transition to expire them after 60 days.

2. A rule in your company states that you should be able to recover your deleted S3 objects immediately for 30 days, although this may happen rarely. After this time, and for up to 365 days, deleted objects should be recoverable within 48 hours.

Standard - Enable versioning so that deleted objects are hidden by a *delete marker* and transition them (non-current versions) to Standard IA.

Deep Archive - Transition the non-current versions using the lifecycle configuration to S3 Deep Archive.
